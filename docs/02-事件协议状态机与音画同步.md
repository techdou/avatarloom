# 事件协议、状态机与音画同步

## Event Envelope

```json
{
  "id": "evt_xxx",
  "type": "transcript.completed",
  "session_id": "ses_xxx",
  "run_id": "run_xxx",
  "timestamp": 0,
  "source": "stt.sensevoice",
  "sequence": 1,
  "payload": {}
}
```

核心事件包括 session、audio、speech、transcript、llm、tts、avatar、vision、persona、response、block、run 和 artifact。

## 显式状态机

```text
IDLE
LISTENING
TRANSCRIBING
THINKING
SPEAKING
INTERRUPTING
ERROR
CLOSED
```

用户在 SPEAKING 状态开口时：取消 LLM、取消 TTS、清空音频、清空 Speech Frame、重置 Avatar，然后进入 LISTENING。

## 音画同步

- 音频是主时钟。
- Speech Frame 按音频播放位置消费。
- Idle Frame 直接显示，不进入口型队列。
- 视频落后时允许跳帧。
- 视频生成慢不得阻塞音频。
- 打断时清空音频和 Speech Frame。
- Avatar 不可用时自动回退 StaticAvatar。

建议配置：

```yaml
sync:
  audioDelayMs: 600
  videoLagFrames: 0
  maxVideoBehindMs: 1000
  dropPolicy: drop_oldest_video
```

Debug Overlay 应显示音频缓冲、视频队列、FPS、解码耗时、音频位置和帧序号。

## 浏览器 ↔ Gateway 通道协议（WS :8101）

> 本节是浏览器与 Runtime Gateway 之间 WebSocket 通道的唯一权威定义。
> 代码侧常量以 `apps/runtime-gateway/.../protocol.py` 与 `apps/studio/lib/frames.ts` 为准。

### 上行（浏览器 → Gateway）

**JSON 控制消息**：

| type | 说明 | payload |
|---|---|---|
| `session.start` | 启动会话 | `{profile_id, persona_id}` |
| `session.stop` | 停止会话 | — |
| `persona.set` | 真切换 Persona（AL-P1-004） | `{persona_id}` |
| `audio.interrupt` | 打断 | — |
| `vision.frame_error` | 截帧失败立即降级 | `{reason}` |
| `ping` | 心跳（前端 20s 间隔） | — |
| `audio.chunk` | JSON 携带 PCM 的遗留通道 | `{pcm_b64, samples}`（新代码请用二进制 0x00） |

**二进制帧（显式 tag，AL-P1-001）**：

| 首字节 | 格式 | 说明 |
|---|---|---|
| `0x00` | `0x00 + PCM16` | 麦克风音频（16kHz int16）。显式 tag 强制——裸 PCM 低字节可能恰为 0x02 造成歧义 |
| `0x02` | `0x02 + JPEG` | 摄像头截帧。Gateway 校验：≤ 2MB（`MAX_CAMERA_FRAME_BYTES`）+ JPEG SOI（`\xff\xd8\xff`） |
| 其他 | — | 未知 tag 一律拒绝；error JSON 每连接只回一次 |

### 下行（Gateway → 浏览器）

**JSON 事件**：`session.started` / `session.state_changed` / `transcript.completed`（含 orchestrator 重发副本 `payload.re_emitted=true`，AL-P1-005）/ `run.started` / `llm.text.delta` / `llm.text.done` / `tts.audio.delta`(meta) / `tts.audio.completed` / `response.done` / `vision.request` / `vision.result` / `avatar.video.ready` / `persona.changed` / `pong` / `error`

**二进制帧**：

| 首字节 | 格式 | 说明 |
|---|---|---|
| `0x01` | `0x01 + subtag + JPEG` | Avatar 帧。subtag：`0x01`=speech（音频时钟消费）、`0x00`=idle（直显） |
| `0x03` | `0x03 + PCM16` | TTS 音频（offset 2 起 Int16 解码，历史对齐） |

### 下行队列策略（AL-P2-006）

三路独立队列，控制绝对优先：

| 队列 | 容量 | 满时策略 | 内容 |
|---|---|---|---|
| control | 512 | 阻塞反压（不丢） | 全部 JSON 事件（含 error / response.done） |
| audio | 64（≈2s） | 丢最旧（跳段） | `0x03` PCM |
| video | 32（≈1.3s） | 丢最旧（跳帧） | `0x01` JPEG |

慢客户端只影响自身音画（跳段跳帧），不反压 Orchestrator 事件出口，且不再丢控制消息。

### 心跳与超时（AL-P2-007）

- 前端连接成功后每 20s 发 `ping`，Gateway 应答 `pong`。
- Gateway `receive()` 90s 无消息 → 判定半开连接，主动断开并 cleanup。

### Vision 调用限制（AL-P1-011）

- Gateway 侧：帧大小 ≤ 2MB、JPEG SOI 校验。
- Orchestrator 侧：同 session 并发锁（同时仅 1 个多模态调用）+ 手动帧 2s 最小间隔；有同轮 pending 的帧不受节流（它是本轮回答前提）。
